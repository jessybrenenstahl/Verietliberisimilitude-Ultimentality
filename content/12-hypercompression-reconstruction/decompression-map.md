# The Decompression Map

Distinguish conceptual dependencies from operational feedback. This map gives reading and reconstruction paths; an arrow here does not claim that the preceding concept logically proves every subsequent one.

| Path | Relation to examine |
|---|---|
| [[axiom]] → [[vls]] / [[semblance]] | Access, accuracy, and non-possession |
| [[directional-primitives]] → [[predicate-binding]] → [[force]] | Actuation, regulated error, and coupled operation |
| [[splcw]] → [[matter-meaning-cycle]] → [[splcw]] | Externalization and return as an operational cycle |
| [[continuable-structure]] → [[continuity]] → [[responsible-successor]] | Inheritance and the additional condition of answerability |
| [[semantic-closure-and-recursive-marking]] → [[correction-without-regress]] | Domain, revision, and usable stopping conditions |
| [[ultimental-kernel]] → [[minimal-rebuild-string]] → [[system-invariants]] | Compressed specification and fidelity assessment |

A rigorous derivation must name its premises and inference. A reading order is not that proof. Feedback can connect already defined functions without making each concept its own justification. Domain applications add explicit carrier facts and constraints; they do not follow from philosophical vocabulary alone.

For maintained relations use [[coupling-graph|the coupling graph]] and [[interaction-matrix|the interaction index]]. A missing diagram edge is a documentation gap unless evidence establishes a missing relation in the framework itself.
